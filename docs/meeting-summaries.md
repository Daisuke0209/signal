# 会議後の要約

リアルタイムの提案は「次に何を言うか」を扱い、会議後の要約は終了した会話の振り返りを扱う。両者を別の状態・API・生成スキーマにして、提案が決定事項として保存されないようにする。

終了後、担当者が「要約を作成」を押すと、確定した発言だけを Responses API に渡す。要約、明示された決定事項、未解決事項、次の対応を返し、会話IDに紐付けて保存する。検索ツールや副作用の操作を与えず、会話にない約束や商品仕様を追加しない指示を使う。品質は人が確定発言と照合する。

POST /conversations/{id}/summary は queued 状態を保存してから処理を開始し、GETで状態と結果を復元する。queued/generating/succeeded の重複POSTは同じ結果を返し追加課金しない。failedのみ明示的な再試行を許可する。会話行のロックで並行開始を直列化し、attempt番号で古い処理の完了を拒否する。DB接続・行ロックを外部API待ちの間は保持しない。

単一APIプロセスで生成は同時に2件まで、外部呼出しは45秒、全体50秒の上限。再起動時のqueued/generatingはfailed/interruptedとして再試行可能にする。ブラウザは画面を離れても保存済み状態を復元できる。分散キューは今後の代替で、今は履歴・失敗・再試行の境界を学べる小さな実装にした。

org認可は開始・取得の両方で確認する。本文をログへ残さず、安全な固定コードだけを保存する。AI生成の有効化設定とAPIキーはサーバーだけで管理する。160000文字を超える会話は切り捨てた要約を作らず413で拒否する。長い会話への分割要約は将来の拡張。

生成境界はモック可能で、保存・重複開始・失敗からの再試行・組織認可をテストする。実モデルによる会議後要約の品質は未検証。リアルタイム提案の実API検証とは区別する。
