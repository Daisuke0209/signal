# PDF検索・営業支援の評価シナリオ

[サンプルPDF](../../output/pdf/signal-demo-product.pdf)は架空の商品「Atlas Desk」の仕様です。
実在商品の情報や顧客情報を含みません。PDFは全3ページ、日本語本文を抽出可能です。
原本のページ番号で引用を確認します。

## 準備

1. ログインしてPDFを登録し、取り込みが成功したことを確認する。
2. 商談を作成し、このPDFを使用する資料として選ぶ。
3. 以下の顧客発言を順に入力する。音声経路を確認するときは、Mac ChromeのMeetで別の参加者から発話する。
4. 提案本文だけでなく、引用先のページ、実行世代、状態の遷移を確認する。

現在の話題に応じた短い質問・返答・確認事項になっていることを評価します。

## 失敗と権限の確認

- PDF未選択: 商品仕様を知っているかのように答えず、資料が必要だと分かる。
- 別組織: 別組織の利用者から資料の検索・原本・ページ・商談へアクセスできない。
- 音声共有キャンセル: 取得中と表示しない。先に取得したトラックも解放する。
- 音声切断: 保存済み会話を保持し、未取得の区間と再開可能な状態が分かる。
- APIタイムアウト: 提案失敗を表示し、古い結果を最新として復活させない。
- 確認依頼の二重承認: 引き継ぎ先へ同じ依頼を重複作成しない。

## リアルタイム性能の記録

暫定目標は途中文字起こしの表示が約1秒以内、発言確定後の提案表示が2〜5秒程度です。
最初の表示、確定、調査開始、提案配信、画面表示の時刻を記録し、回線・モデル・音声条件も残します。
長い調査では「調査中」を表示することを別に確認します。

モックでのイベント順序・状態遷移の検証と、実APIでの動作・実Meet音声での遅延測定を分けます。
この資料追加時点では、PDFの描画と日本語本文抽出のみ検証済みです。
アプリ経由の検索・提案・実音声の結果は、該当機能のIssueに実施後の証拠を記録します。
UIを変更したIssueには、実際に起動したアプリのスクリーンショットを掲載します。
